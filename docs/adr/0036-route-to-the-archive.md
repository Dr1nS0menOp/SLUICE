# ADR 0036: In Sentinel, events no rule could match stay in the archive table only

- Status: Accepted (branch `study/theory`)
- Date: 2026-10-30

## Context

Sluice's savings rest on three guarantees (docs/notes/field-theory.md): the rules see what they
read, nothing is lost, and every event stays searchable somewhere. Where no rule could match an
event of a frequent kind, Vector counts it into a summary record instead of sending it (L2). A
data collection rule cannot count, so in Sentinel's own ingestion (`--native sentinel`, ADR 0013)
those events went into the analytics table in full.

But the rule Sluice writes already has a second flow, untransformed, into an archive table on
the Auxiliary plan (contract rule 2). In West Europe on 2026-10-30 a GB costs $5.59 in the
analytics table and about $0.20 in the data lake (ingestion and processing), plus $0.024 a month
to keep. An event the archive holds whole does not need to be in the analytics table for the
rules, by guarantee 1, and stays searchable, by guarantee 3.

## Decision

1. **`--native sentinel` routes.** For a group of records the transformation recognises
   exactly (ADR 0013) whose every template counts instead of sending (`count_instead` in the
   plan), the transformation adds `| where not(<the group> and not(<forward_when>))`: a record of
   such a group that no rule could match stays out of the analytics table's flow. The archive
   flow next to it is untouched, so the record is kept whole there. `forward_when` compiles to
   KQL that matches at least what Vector's VRL matches (ADR 0013), so no record Vector sends is
   kept out.
2. **Only with the archive flow.** Routing is generated by `sluice_kql::routed_within` and
   `routed_on_within`; `transformation_within` keeps L1 only. The CLI uses the routed form
   because the rule it writes always has the archive flow; without `--sentinel-dcr` nothing is
   written.
3. **What stays.** A group that also holds a template sending every event, or records a template
   the transformation cannot recognise could also have, keeps every record (contract rule 1),
   and the report's "left out" says why. Records of a template that counts get no summary record
   in the analytics table: the archive holds the events themselves.
4. **The proof.** The native proof (`through_flow`) accepts a record the transformation keeps out
   only if Vector counts it too (the data plane's outcome is not `Forwarded`), and compares the
   Sentinel rules' alerts over every record as the table stores it without the transformation
   with their alerts over what the transformation leaves.

## Consequences

- On OTRF's APT29 day 1 with the example rules, priced per month at the sample's rate: everything
  in the analytics table $2,615; Sluice's plan in Vector alone $572 (78.1 % less); the same with
  every event whole in the data lake $674 (74.2 % less); routing with the archive $636 (75.7 %
  less) (`scripts/research/tiers.py`). Keeping every event searchable costs 2 to 4 points of the
  saving.
- Tested: unit tests of the generated KQL, and in the Kusto emulator
  (`c3_in_the_kql_engine_only_records_no_rule_could_match_stay_out`): exactly the counting
  template's records that no rule could match are kept out; one a rule could match, one of
  another kind and one with an extra column stay.
- **Not yet seen end to end on real data.** On the samples at hand that are in a Sentinel
  table's shape (the test workspace's `SecurityEvent` with the Windows Security Events solution,
  the demo's sources in custom tables with Sentinel rules from files), Sluice counts nothing, so
  nothing is routed; a nested discriminator (`event.dataset`) also keeps a kind of event from
  being recognised in a data collection rule. Routing pays off once a source in a Sentinel table
  has kinds of event Sluice counts, as APT29's Sysmon has with Sigma rules in Vector.
- Searching what is kept out means searching the archive table: slower, and charged per GB
  scanned. `<Table>Full` reads the analytics table only.
- Elasticsearch, Fluent Bit and the collector are not changed: an ingest pipeline that drops a
  document has no archive next to it in the same step.
